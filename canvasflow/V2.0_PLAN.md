# CanvasFlow v2.0 — Precision Canvas & Transform Studio

**Planning specification**  
**Baseline:** CanvasFlow v1.9.0 — Advanced Layout Studio  
**Planned project schema:** v12 (subject to implementation audit)  
**Product type:** Local-first visual website builder that exports ordinary, editable HTML, CSS, JavaScript where needed, and local assets. CanvasFlow remains a design-and-code tool; it does not host or publish the user's website.

---

## 1. Product goal

Make CanvasFlow's canvas feel like a professional visual design workspace while preserving the web-first layout engine introduced in v1.8 and extended in v1.9.

The defining rule is:

> **Responsive document flow remains the default. Free positioning is explicit, parent-relative, and breakpoint-aware.**

Users should be able to build an ordinary responsive website with Stack, Flexbox and Grid, but also switch selected elements into a positioning mode when they need precise composition, overlap, rotation or canvas-style placement.

v2.0 is successful when a user can place, size, align and refine an element accurately at any editor zoom, without corrupting responsive layouts or producing fragile exported code.

## 2. What v1.9 already does — do not rebuild it

The v1.9 source already includes:

- Stack, Flexbox and Grid layouts, nested containers, responsive container settings and saved layout presets.
- A preview iframe with a sandboxed editor interaction bridge and postMessage events.
- Selection from the preview and Layers tree; same-parent multi-selection is capped at 20 items.
- Batch flow alignment (left, centre, right, stretch) and shared sibling-gap presets.
- Drag-reordering of normal-flow siblings, including nested siblings.
- A bottom-right resize handle for supported elements, 8 px resize snapping, sibling-dimension snapping, Shift aspect-ratio support where applicable, and Escape/pointer-cancel rollback.
- Decorative overlay positioning for shapes and vectors using section-relative percentages; overlay snapping, keyboard nudging, z-order and grouping.
- Dynamic alignment/spacing guides, a 16 px visual grid, 100 px rulers and a Fit-to-canvas option.
- Responsive Desktop, Tablet and Mobile previews, per-breakpoint overrides, multi-page export, components, design tokens, assets, typography, vector drawing, animation and interaction features.

These should be regression-protected, not recreated.

### Important v1.9 limitations that v2.0 should solve

| Area | Current limitation | v2.0 direction |
|---|---|---|
| Canvas camera | Fit is available, but there is no true zoom percentage or pan workflow | Independent zoom and pan controls |
| Guides | Existing guides are automatically generated; users cannot create and manage their own ruler guides | Draggable, editable, lockable guide lines |
| Snapping | Existing snapping is specialised for overlays and resizing | One geometry-based snapping system for supported transforms |
| Positioning | Free positioning is limited to decorative shape/vector overlays | Explicit Flow / Free-position modes for regular content nodes |
| Transform handles | The preview has a bottom-right resize handle | Full resize handles, move and rotation controls for free-positioned nodes |
| Numeric precision | Some dimensions and overlay percentages are editable, but there is no unified transform panel | One X / Y / W / H / rotation inspector |
| Geometry arrangement | Existing multi-select primarily applies flow alignment; overlay groups move together | Geometric alignment and distribution for free-positioned selections |
| Zoom-aware interaction | No zoom state exists to coordinate with hit-testing and snap tolerance | Stable pointer mapping and screen-consistent snapping at every zoom |

## 3. v2.0 feature scope

### A. Canvas navigation and zoom

**Required**

- Zoom levels: 25%, 33%, 50%, 67%, 75%, 100%, 125%, 150%, 200% and Fit.
- Zoom in/out buttons and a numeric zoom indicator/menu.
- Zoom towards the pointer position rather than always towards the canvas centre.
- Pan with Space + drag and middle mouse on desktop; provide a dedicated Hand tool for touch devices.
- Fit canvas and centre selection commands.
- Keep the actual website viewport width independent from editor zoom. For example, a 390 px Mobile preview remains a 390 CSS-pixel website even when displayed at 75% editor zoom.
- Preserve zoom/pan during selection and property editing; reset or fit on page/device change only by an explicit rule.

**Interaction rules**

- Ctrl/Cmd + wheel zooms the editor canvas; ordinary wheel/trackpad scroll remains available for page navigation.
- Ctrl/Cmd + `+` / `-` zooms; Ctrl/Cmd + `0` returns to 100%; a separate Fit shortcut is documented.
- Space temporarily activates Hand mode unless a text field is focused.
- Touch supports pinch zoom and two-finger pan; one-finger gestures continue to edit the selected object when in Select mode.

### B. Flow and Free-position modes

Every eligible content element starts in **Flow** mode. This keeps normal website layout reliable.

Add an explicit **Positioning** control:

- **Flow:** element participates in its parent's Stack/Flexbox/Grid layout. Dragging continues to reorder or change layout, not invent arbitrary coordinates.
- **Free position:** element is removed from normal flow and can be moved within its containing section/container. It may overlap siblings intentionally.

For Free-position elements:

- Store position relative to the containing layout parent's content box, not the browser window or editor screen.
- Expose X and Y with px and % units, plus width and height, rotation, and stacking order.
- Keep position, size and rotation independently overridable at Desktop, Tablet and Mobile.
- Make the containing block explicit in the Layers tree and inspector; nested containers establish their own positioning context.
- Add a safe minimum-height/empty-canvas rule so a parent containing only free-positioned children does not collapse to zero height.
- Never silently convert a Flow element to Free position because the user dragged it. The user must choose the mode or confirm the conversion.
- Converting Flow → Free position captures the element's current rendered location and size relative to its parent as closely as practical. Converting Free position → Flow restores it to normal flow and retains its content/style; warn that exact visual placement may change because flow layout controls the final position.

**Compatibility rule:** existing v1.9 `positionMode: "overlay"` shapes/vectors keep their established section overlay behavior. They must not be reinterpreted as the new Free-position mode during migration.

### C. Transform controls and handles

For Free-positioned elements:

- Eight resize handles (four corners and four edges).
- A move region/bounding box with clear selection affordance.
- A rotation handle with a visible angle readout.
- Exact X, Y, Width, Height and Rotation fields in the inspector.
- Lock/unlock aspect ratio; Shift temporarily constrains proportions during pointer resize.
- Optional centre/pivot indicator, with a clear default of centre rotation.
- Flip horizontal/vertical may be included only if the transform model and exported CSS can preserve it cleanly; it is lower priority than core move/resize/rotate.

For Flow elements:

- Preserve current reorder and layout-aware resize behaviour.
- Do not show X/Y controls that imply absolute placement.
- Use the same numeric width/height controls where the element supports them.

**Gesture correctness:** one complete drag/resize/rotate is one undo action. Escape and pointer-cancel restore the pre-gesture state. A pointer leaving the iframe or losing capture must not leave the editor stuck in an interaction state.

### D. Unified smart guides and snapping

Build a shared geometry service rather than adding separate snap calculations to each gesture.

Snap targets:

- Parent content edges and centre lines.
- Sibling left/right/top/bottom edges and centres.
- Other selected/unselected Free-position elements where valid.
- Grid intersections and user-created guides.
- Equal-spacing opportunities between nearby objects.

Snap options:

- Grid on/off and configurable grid interval (4, 8, 16, 24, 32 px plus custom value).
- Snap to grid, parent, siblings, guides and equal spacing can be toggled independently.
- Horizontal and vertical snapping can be toggled separately.
- Alt temporarily bypasses snapping, preserving current shortcut behaviour.
- Snap tolerance is measured in screen pixels and converted by zoom, so snapping feels consistent at 25% and 200% zoom.
- Display a clear smart-guide line and a small label for the snapped edge, centre, distance or spacing.
- Avoid snapping to selected siblings or to the dragged item's own group.

### E. User-created ruler guides

- Drag from the horizontal or vertical ruler to create a guide.
- Move an existing guide by dragging it; double-click or use the inspector to enter an exact coordinate.
- Lock/unlock, hide/show, and delete individual guides.
- Offer an option to clear all guides on the active page.
- Store guides in editor-only page metadata, optionally separated by Desktop/Tablet/Mobile canvas viewport.
- Guides are included in editable project backups but never appear in generated website HTML/CSS or screenshots of the export.

### F. Alignment, distribution and multi-selection

Retain current Flow alignment and extend it with geometry-aware actions for Free-positioned items sharing the same parent.

**Align:** left, horizontal centre, right, top, vertical centre, bottom.  
**Distribute:** equal horizontal spacing and equal vertical spacing.  
**Size:** match width, match height, and (where appropriate) match both dimensions.  
**Nudge:** arrow keys for small movement; Shift for larger movement; Alt for fine movement. The displayed increment must adapt to the selected unit and current zoom only for interaction feel, not alter stored values unpredictably.

Rules:

- A geometric multi-selection must share a common positioning parent.
- Mixed Flow and Free-position selections show only operations that are valid for the entire selection.
- Grouped overlay behaviour from v1.9 remains intact.
- Multi-select transforms keep relative spacing and are reversible in one undo step.
- Do not turn a CSS `align-self` action into fixed pixel coordinates.

### G. Inspector and interaction polish

- Add a compact **Arrange / Transform** property group that appears only when applicable.
- Show units beside each field; reject NaN, Infinity, out-of-bounds and malformed values.
- Support arrow-key increments and direct text entry; Enter commits, Escape cancels the field edit.
- Expose the parent/coordinate reference in the inspector (for example, “Relative to: Feature container”).
- Maintain selection when an inspector value is updated; do not jump the user to the first layer after each change.
- Add clear hover, selected, focused, locked and snapping states.
- Make all controls usable by keyboard and touch; don't rely on colour alone to convey snap or selection state.

## 4. Deliberately out of scope for v2.0

To keep this major release coherent and testable, defer:

- Full animation/keyframe timeline redesign.
- Collaborative multiplayer editing and cloud sync.
- AI site generation.
- Publishing/hosting, accounts, domains or paid subscriptions.
- Arbitrary user-authored CSS/JavaScript.
- A complete vector-node/path editor redesign.
- Nested reusable component architecture changes.
- A general-purpose freeform connector/wire tool.

These can be considered for later milestones without blocking the precision workspace.

## 5. UX layout proposal

### Canvas toolbar

Keep the current insert tools, but add a distinct **Canvas** group:

- Select / Hand tools.
- Zoom out, zoom percentage menu, zoom in, Fit.
- Snap menu with independent target toggles.
- Grid menu with interval.
- Guides visibility and clear-guide action.

Avoid putting every advanced setting directly on the toolbar. Use small menus/popovers so the canvas remains spacious, especially on mobile.

### Properties inspector

When one Free-positioned node is selected:

1. Positioning mode + parent reference.
2. Position: X, Y and units.
3. Size: W, H and aspect lock.
4. Transform: rotation and pivot.
5. Arrange: align/distribute actions when multiple nodes are selected.
6. Existing visual styling, responsive settings, motion and layer properties remain in their current groups.

### Layers tree

- Distinguish Flow and Free-position nodes with a small text/icon indicator.
- Show the containing parent clearly.
- Preserve nested-container collapse/expand, visibility, lock, z-order and selection.
- Keep layer-tree reordering rules explicit: same-parent reordering remains supported; moving a node to a different parent requires a deliberate drop target and validation.

## 6. Technical architecture

### Existing architecture to preserve

- `src/model.js`: project normalization, node tree, CSS/HTML generation and sandboxed preview document.
- `src/app.js`: UI state, selection, inspector, mutation handlers and preview message bridge.
- `src/history.js`: bounded undo/redo manager.
- `src/project-storage.js`: resilient local persistence and legacy-key recovery.
- `src/zip.js`: dependency-free export/backup ZIP generation.
- `styles.css` and `index.html`: responsive studio UI.
- `tests/model.test.js`: automated model, export, storage and UI-wiring regression tests.

Continue using the structured project model as the source of truth. The DOM may provide measured geometry during a gesture, but DOM measurements must not become the saved document model without conversion to validated model fields.

### Proposed schema v12 additions

Final property names should be confirmed during the implementation audit, but the model needs these concepts:

- A new explicit Free-position mode distinct from the existing `overlay` mode.
- Parent-relative X/Y values and units.
- Rotation angle and rotation origin.
- Responsive overrides for position, dimensions and rotation.
- Per-page editor-only guides and optional grid preferences.

All imported values must pass allowlists and numeric bounds. Preserve existing v11 fields and do not rewrite old overlay positions. Guide metadata is persisted in project backups but excluded from exported website files.

### Preview bridge contract

Extend the existing `canvasflow:*` postMessage protocol with a small, validated set of transform events. Validate message type, IDs, numeric values, bounds, parent relationships and lock state in the parent application before changing the model. Do not accept HTML, CSS or JavaScript snippets from the iframe. Keep the preview iframe sandboxed.

### Geometry service

Create pure helpers for:

- Converting pointer coordinates to parent-relative document coordinates at the current zoom.
- Resolving effective breakpoint values.
- Calculating selection bounds and rotated bounds.
- Resizing from each handle while respecting aspect lock and minimum/maximum dimensions.
- Computing snap candidates and priority/tie-break rules.
- Aligning and distributing a selected set of nodes.

The service should receive measured rectangles and normalized model values; it should not query the DOM itself. This keeps it testable without a browser.

### CSS/export rules

- Flow nodes continue to emit normal Stack/Flexbox/Grid CSS.
- Free-position nodes emit ordinary CSS positioned relative to the nearest declared parent.
- Rotation uses CSS transforms with a stable transform origin.
- Breakpoint overrides emit normal media queries using the project's established breakpoint system.
- Editor grid, rulers, user guides, selection boxes, resize handles, snap labels and zoom/pan UI must never enter exported HTML/CSS.
- Exported sites continue to work without a CanvasFlow runtime dependency for layout or editing.

## 7. Implementation phases and gates

### Phase 0 — Baseline and design lock

- Preserve the exact v1.9.0 ZIP as the rollback baseline.
- Run its current checks and all 95 existing tests before editing.
- Document current node geometry, preview bridge messages and responsive inheritance.
- Finalize coordinate reference rules and interaction shortcuts before changing the model.

**Gate:** no implementation begins until Flow vs Free-position behaviour and parent coordinate semantics are unambiguous.

### Phase 1 — Canvas camera

- Add zoom state, percentage UI, zoom-to-pointer, Fit and pan.
- Ensure preview iframe CSS viewport width is unchanged by editor zoom.
- Implement desktop shortcuts and touch Hand/pinch behaviour.

**Gate:** at every zoom level, selection hit-testing and existing overlay dragging still target the correct element.

### Phase 2 — Schema and Free-position model

- Add schema v12 migration and bounded transform fields.
- Add explicit Flow / Free-position conversion actions.
- Render and export Free-position nodes relative to their actual parent.
- Preserve old v1.9 overlay shapes and vectors exactly.

**Gate:** import v1.9 project, save, reopen and export with no lost content, IDs, assets, components or responsive styles.

### Phase 3 — Transform handles and inspector

- Add eight resize handles, move, rotate and numeric Transform controls.
- Add aspect lock and keyboard nudging.
- Make each gesture transactional for undo/redo and rollback.

**Gate:** pointer, keyboard and touch edits produce the same model geometry and are fully reversible.

### Phase 4 — Smart guides, snapping and ruler guides

- Extract the geometry/snap engine into pure helpers.
- Add configurable grid and snap targets.
- Add user-authored guides with coordinate editing, locking and deletion.
- Make snap tolerance stable across zoom levels.

**Gate:** snapping remains predictable at 25%, 50%, 100%, 150% and 200%; editor-only guides never appear in exports.

### Phase 5 — Multi-selection arrangement

- Extend transform bounds to compatible same-parent Free-position selections.
- Add geometric alignment, distribution and match-size actions.
- Retain existing Flow alignment and overlay grouping without changing semantics.

**Gate:** mixed-parent and mixed-mode selections are safely rejected or expose only valid actions; group movement and undo remain deterministic.

### Phase 6 — Hardening and release candidate

- Complete migration/import/export, responsive and interaction tests.
- Audit HTML IDs, CSS syntax, local references, ZIP integrity and server routes.
- Test exports by opening them separately from the editor.
- Perform actual browser testing in Chrome/Edge and Android touch where the environment permits; clearly report any manual test not completed.

**Release gate:** all previous tests pass, all new v2.0 tests pass, extracted ZIP passes independently, and there are no known data-loss or export-blocking defects.

## 8. Acceptance test matrix

### Compatibility and project safety

- Open a v1.9.0 project containing multi-page content, nested containers, components, vectors, overlays, assets and responsive overrides.
- Confirm all pages and IDs survive migration to v12.
- Save, refresh, reopen, backup, import and export the migrated project.
- Import representative older schema backups and confirm their content is preserved.

### Canvas navigation

- Test every zoom preset and zoom-to-pointer near each canvas edge.
- Pan using Space, middle mouse and Hand mode.
- Test browser zoom separately from CanvasFlow zoom.
- Confirm device viewport widths remain exactly as selected at every editor zoom.

### Position and transform

- Convert each supported content type Flow → Free position → Flow.
- Move, resize from all eight handles, rotate, edit exact fields, lock aspect ratio and test minimum/maximum bounds.
- Test children in sections and nested containers to confirm coordinates use the correct parent.
- Test overlapping elements, z-order, hidden and locked layers.
- Test undo/redo and Escape/pointer-cancel for every gesture.

### Snapping and guides

- Test grid, parent edge/centre, sibling edge/centre and equal-gap snapping independently.
- Test Alt bypass and axis-specific snapping.
- Repeat at 25%, 50%, 100%, 150% and 200% zoom.
- Create, move, numerically edit, lock, hide and delete ruler guides.
- Confirm guides and editor overlays are absent from website exports.

### Responsive behaviour

- Position and size an element independently on Desktop, Tablet and Mobile.
- Confirm Mobile inheritance from Tablet when no explicit override exists.
- Switch breakpoints during and after edits; confirm no value leaks into another breakpoint.
- Export and inspect at narrow, tablet and desktop CSS viewport widths.

### Multi-selection and accessibility

- Select multiple compatible nodes under one parent; move, resize, rotate, align and distribute.
- Attempt mixed-parent, Flow/Free-position and locked-node selections.
- Test keyboard-only selection, inspector entry, nudging and action access.
- Test touch targets, pinch/pan conflicts and resize handles on Android.

### Export and quality

- Export a multi-page project with nested containers, Free-position elements, overlays, images, vectors and interactions.
- Open the exported site independently and verify all assets, page links, positioning and responsive rules.
- Confirm no editor selection styles, ruler, grid, guides, handles or preview bridge scripts leak into the export.
- Run syntax checks, the full automated suite, CSS parsing, duplicate-ID audit, local-reference audit, server smoke tests and extracted-ZIP tests.

## 9. Proposed release acceptance criteria

v2.0.0 is ready only when:

1. Every v1.9.0 feature still works; no planned deletion or redesign of unrelated studios.
2. Canvas zoom changes only editor presentation, not the website CSS viewport.
3. Free positioning is explicit and parent-relative; Flow stays the default.
4. Position, size and rotation are editable both directly on canvas and numerically.
5. Snapping and user guides work predictably at all zoom levels.
6. Desktop, Tablet and Mobile values remain independent and export as ordinary CSS.
7. Transform gestures are atomic, reversible and cancel safely.
8. Project schema migration, editable backups and multi-page website export are verified.
9. The extracted release archive passes tests independently.
10. Browser testing limitations are disclosed rather than marked as passed.

## 10. Recommended build order

The safest order is **Canvas Camera → Position Model → Transform Handles → Smart Guides → Multi-selection → QA**. Do not start with rotation handles or more toolbar buttons before the coordinate system and parent-relative positioning model are stable.

This makes v2.0 a genuine architectural milestone: a precise editor on top of CanvasFlow's existing responsive layout engine, without sacrificing clean code export.
